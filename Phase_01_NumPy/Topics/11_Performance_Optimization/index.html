Performance Optimization: Memory Layout & Views — পারফরম্যান্স অপ্টিমাইজেশন: C বনাম Fortran লেআউট ও ভিউ

মেমোরি ক্যাশ লোকালিটি এবং ইন-প্লেস অপারেশন। C-Contiguous (Row-major) বনাম Fortran (Column-major) মেমোরি অর্ডার এবং অনিচ্ছাকৃত ডেটা কপি প্রতিরোধ করে হাই-স্পিড কোডিং।

০১ থিওরি ও মূল কনসেপ্ট (Theory & Core Concepts)

মেমোরি সংলগ্নতা (Contiguity) ও ক্যাশ লোকালিটি

সিপিইউ ক্যাশ মেমোরি থেকে ডেটা রিড করার সময় সবচেয়ে বেশি গতি পায় যখন উপাত্তগুলো মেমোরিতে পরপর সাজানো থাকে।

  • C-Order (Row-Major - ডিফল্ট):
    মেমোরিতে একটি সারির সব উপাদান পাশাপাশি থাকে। তাই সারি বরাবর ইটারেশন অত্যন্ত দ্রুত হয়।
  • Fortran-Order (Column-Major):
    কলামের উপাদানগুলো মেমোরিতে পাশাপাশি থাকে। কলাম বরাবর অপারেশন দ্রুত হয়।
  • View বনাম Copy সচেতনতা:
    স্লাইসিং করলে একটি View তৈরি হয় (মেমোরি শেয়ার করে)। কিন্তু ফ্যান্সি ইনডেক্সিং বা মাস্কিং করলে একটি নতুন Copy তৈরি হয় যা র‍্যাম অপচয় করতে পারে।
  • ইন-প্লেস অপারেশন (In-place Mutation):
    a = a + 1 নতুন অ্যারে তৈরি করে।
    a += 1 একই মেমোরিতে আপডেট করে (শূন্য মেমোরি ওভারহেড)।

০২ বাস্তব কোড উদাহরণ (Real-World Code Example)

numpy_performance_memory.py 
import numpy as np

# ১. C-Contiguous বনাম Fortran-Contiguous মেমোরি ফ্ল্যাগ
c_array = np.ones((1000, 1000), order='C')
f_array = np.ones((1000, 1000), order='F')

print("C-Array Flags:")
print("  C_CONTIGUOUS:", c_array.flags['C_CONTIGUOUS'])
print("  F_CONTIGUOUS:", c_array.flags['F_CONTIGUOUS'])

# ২. View বনাম Copy পরীক্ষা (shares_memory)
base_arr = np.array([10, 20, 30, 40, 50])
sliced_view = base_arr[1:4]             # View (No Copy)
fancy_copy = base_arr[[1, 2, 3]]        # Copy (Allocates new RAM)

print("\nMemory Sharing Check:")
print("Does Slice share memory?:", np.shares_memory(base_arr, sliced_view))
print("Does Fancy Index share memory?:", np.shares_memory(base_arr, fancy_copy))

# ৩. ইন-প্লেস অপারেশনের জাদু
orig_id = id(base_arr)
base_arr += 5  # In-place addition
print("Memory Address Preserved after += :", id(base_arr) == orig_id)
🖥️ Terminal Output 
C-Array Flags:
  C_CONTIGUOUS: True
  F_CONTIGUOUS: False

Memory Sharing Check:
Does Slice share memory?: True
Does Fancy Index share memory?: False
Memory Address Preserved after += : True

💡 কোড বিশ্লেষণ ও ব্যাখ্যা (Line-by-Line Breakdown):

• np.shares_memory(base_arr, sliced_view): True প্রকাশ করে যে স্লাইসিং কোনো অতিরিক্ত মেমোরি খরচ করেনি।
• base_arr += 5: মেমোরি অ্যাড্রেস অক্ষুণ্ণ রেখে ইন-প্লেস ডেটা পরিবর্তন করেছে।
