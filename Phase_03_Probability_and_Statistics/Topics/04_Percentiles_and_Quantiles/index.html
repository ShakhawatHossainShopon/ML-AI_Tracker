Phase 03: Topic 04 Mobile View

Percentiles, Quantiles & Interquartile Range (IQR) — পার্সেন্টাইল, কোয়ান্টাইল ও IQR: ডেটার অবস্থান ও অ্যানোমালি ডিটেকশন

সার্ভার রেসপন্স ল্যাটেন্সি মনিটরিং (p95, p99) এবং ইন্টারকোয়ার্টাইল রেঞ্জের (IQR) মাধ্যমে ডেটাসেট থেকে স্বয়ংক্রিয় আউটলায়ার অপসারণ।

০১ থিওরি ও মূল কনসেপ্ট (Theory & Core Concepts)

পার্সেন্টাইল ও IQR: এআই ইঞ্জিনিয়ারিংয়ে কেন এত গুরুত্বপূর্ণ?

যখন উপাত্ত চরমভাবে অসম বা স্কিউড হয়, তখন গড় ও স্ট্যান্ডার্ড ডেভিয়েশন অকার্যকর হয়ে পড়ে। তখন আমরা ডেটাকে সমান অনুপাতে বিভক্ত করে অবস্থানগত বিশ্লেষণ করি।

  • পার্সেন্টাইল (Percentile): উপাত্তের শতকরা কত অংশ কোনো নির্দিষ্ট মানের নিচে রয়েছে।
    উদাহরণ: আপনার টেস্ট স্কোর ৯০তম পার্সেন্টাইলে থাকার অর্থ আপনি ৯০% পরীক্ষার্থীর চেয়ে বেশি নম্বর পেয়েছেন।
  • p95 এবং p99 লেটেন্সি (SRE & Backend Metric): সফটওয়্যার ইঞ্জিনিয়ারিংয়ে গড় রেসপন্স টাইম কোনো কাজের নয়। ৯৫% বা ৯৯% ইউজার ঠিক কত দ্রুত সার্ভিস পাচ্ছেন তা p95 ও p99 পার্সেন্টাইল দিয়ে পরিমাপ করা হয়।
  • কোয়ার্টাইল (Quartiles - Q1, Q2, Q3): ডেটাকে চারটি সমান ২৫% ভাগে ভাগ করা।
    • Q1 (25th Percentile): প্রথম এক-চতুর্থাংশ মান।
    • Q2 (50th Percentile): মধ্যক (Median)।
    • Q3 (75th Percentile): তিন-চতুর্থাংশ মান।
  • ইন্টারকোয়ার্টাইল রেঞ্জ (IQR = Q3 - Q1): মাঝের ৫০% ডেটার বিস্তৃতি।
    আউটলায়ার ডিটেকশন রুল:
    Lower Bound = Q1 - 1.5 * IQR
    Upper Bound = Q3 + 1.5 * IQR
    এই সীমার বাইরের যেকোনো ডেটা পয়েন্টকে স্বয়ংক্রিয়ভাবে আউটলায়ার বা অ্যানোমালি গণ্য করা হয়।

০২ বাস্তব কোড উদাহরণ (Real-World Code Example)

percentiles_iqr_detector.py 
# -------------------------------------------------------------
# Topic 04: Percentile (p95, p99) & IQR Outlier Filter
# -------------------------------------------------------------

def calculate_percentile(sorted_data, p):
    """লিনিয়ার ইন্টারপোলেশন পদ্ধতিতে পার্সেন্টাইল নির্ণয়"""
    n = len(sorted_data)
    if n == 0:
        return 0
    k = (n - 1) * (p / 100.0)
    f = int(k)
    c = f + 1 if f + 1 < n else f
    d = k - f
    return sorted_data[f] + d * (sorted_data[c] - sorted_data[f])

# একটি এআই এপিআই সার্ভারের রেসপন্স টাইম (মিলিসেকেন্ডে - ms)
latencies = [120, 125, 130, 128, 135, 140, 132, 138, 122, 129, 
             145, 150, 131, 127, 133, 450, 890, 1200] # শেষের ৩টি চরম স্লো রিকোয়েস্ট

latencies.sort()

# ১. SRE লেটেন্সি মেট্রিক্স
p50 = calculate_percentile(latencies, 50)
p90 = calculate_percentile(latencies, 90)
p95 = calculate_percentile(latencies, 95)
p99 = calculate_percentile(latencies, 99)

# ২. IQR আউটলায়ার বাউন্ডিং ক্যালকুলেশন
q1 = calculate_percentile(latencies, 25)
q3 = calculate_percentile(latencies, 75)
iqr = q3 - q1
lower_bound = q1 - 1.5 * iqr
upper_bound = q3 + 1.5 * iqr

outliers = [x for x in latencies if x < lower_bound or x > upper_bound]
cleaned_data = [x for x in latencies if lower_bound <= x <= upper_bound]

print("=== Server Latency Percentiles ===")
print(f"p50 (Median) : {p50:.1f} ms")
print(f"p90 Latency  : {p90:.1f} ms")
print(f"p95 Latency  : {p95:.1f} ms")
print(f"p99 Latency  : {p99:.1f} ms")
print("-" * 50)
print(f"Q1 (25%) = {q1:.1f} ms | Q3 (75%) = {q3:.1f} ms | IQR = {iqr:.1f} ms")
print(f"Valid Range  : [{lower_bound:.1f} ms to {upper_bound:.1f} ms]")
print(f"Detected Outliers : {outliers} ms")
print(f"Cleaned Mean Latency : {sum(cleaned_data)/len(cleaned_data):.2f} ms (Raw Mean: {sum(latencies)/len(latencies):.2f} ms)")

💡 কোড বিশ্লেষণ ও ব্যাখ্যা (Line-by-Line Breakdown):

১. p50 বনাম p99: অর্ধেকের বেশি ইউজার ১৩২.৫ মিলিসেকেন্ডে রেসপন্স পেলেও দুর্ভাগ্যজনক ১% ইউজারকে ১১৫০.৭ মিলিসেকেন্ডের বেশি অপেক্ষা করতে হচ্ছে।
২. IQR আউটলায়ার সীমানা: IQR মাত্র ১৬.৫ মিলি-সেকেন্ড হওয়ায় স্বাভাবিক রেঞ্জ দাঁড়িয়েছে ১০২.৫ থেকে ১৬৮.৫ ms। ফলে অস্বাভাবিক [450, 890, 1200] ms নিখুঁতভাবে চিহ্নিত হয়েছে।
৩. ক্লিনড ডেটা গড়: আউটলায়ার ফিল্টার করায় গড় ২৫১.৩৯ ms থেকে কমে বাস্তবসম্মত ১৩১.৮৭ ms এ ফিরে এসেছে, যা মডেল প্রশিক্ষণের গুণমান বহুগুণ বাড়িয়ে দেয়।
