০১ থিওরি ও মূল কনসেপ্ট (Theory & Core Concepts)

গ্লোবাল পাইথনে প্যাকেজ ইনস্টল করা কেন নিষিদ্ধ?

আপনি যদি সরাসরি অপারেটিং সিস্টেমের গ্লোবাল পাইথনে প্যাকেজ ইনস্টল করেন, তবে একটি প্রজেক্টের জন্য ইনস্টল করা লাইব্রেরি অন্য প্রজেক্টের লাইব্রেরির সাথে কনফ্লিক্ট করবে (Dependency Hell)। যেমন: একটি প্রজেক্টে PyTorch 1.12 লাগলে এবং অন্যটিতে PyTorch 2.4 লাগলে গ্লোবাল এনভায়রনমেন্ট ভেঙে পড়বে। ভার্চুয়াল এনভায়রনমেন্ট এর নিখুঁত সমাধান:

  • Virtual Environment (venv): প্রতিটি প্রজেক্টের জন্য সম্পূর্ণ আলাদা একটি পাইথন বাইনারি ও প্যাকেজ ডিরেক্টরি তৈরি করে। এক প্রজেক্টের লাইব্রেরি অন্য প্রজেক্টকে স্পর্শ করতে পারে না।
  • কমান্ড: python -m venv venv (এনভায়রনমেন্ট তৈরি) এবং source venv/bin/activate (উইন্ডোজে venv\Scripts\activate)।
  • Pip: পাইথনের অফিসিয়াল প্যাকেজ ম্যানেজার যা PyPI রিপোজিটরি থেকে লাইব্রেরি নামিয়ে দেয় (যেমন: pip install numpy torch)।
  • requirements.txt: প্রজেক্টের সমস্ত ডিপেন্ডেন্সি ভার্সন লক করে রাখতে pip freeze > requirements.txt করা হয়। অন্য কোনো মেশিনে বা ক্লাউডে হুবহু একই সেটআপ তৈরি করতে pip install -r requirements.txt ব্যবহার করা হয়।

ইন্ডাস্ট্রি রুল: নতুন যেকোনো এআই বা সফটওয়্যার রিপোজিটরি ক্লোন করার পর সবার প্রথম কাজ হলো একটি ভার্চুয়াল এনভায়রনমেন্ট চালু করা।

০২ বাস্তব কোড উদাহরণ (Real-World Code Example)

env_inspector.py 
import sys
import os

def inspect_environment():
    # ভার্চুয়াল এনভায়রনমেন্ট সক্রিয় আছে কিনা যাচাই
    in_venv = sys.prefix != sys.base_prefix
    
    print("--- পাইথন এনভায়রনমেন্ট টেলিমেট্রি ---")
    print(f"পাইথন এক্সিকিউটেবল : {sys.executable}")
    print(f"পাইথন সংস্করণ       : {sys.version.split()[0]}")
    print(f"ভার্চুয়াল এনভায়রনমেন্ট : {'✅ সক্রিয় (Active)' if in_venv else '❌ গ্লোবাল (Global)'}")
    
    # ডেমো ডিপেন্ডেন্সি ম্যানিফেস্ট জেনারেশন
    simulated_packages = {
        "numpy": "1.26.4",
        "pandas": "2.2.1",
        "torch": "2.2.0+cu121",
        "scikit-learn": "1.4.1"
    }
    
    manifest_lines = [f"{pkg}=={ver}" for pkg, ver in simulated_packages.items()]
    print("\n--- requirements.txt প্রিভিউ ---")
    print("\n".join(manifest_lines))

inspect_environment()

💡 কোড বিশ্লেষণ ও ব্যাখ্যা (Line-by-Line Breakdown):

sys.prefix != sys.base_prefix: ওএস সিস্টেম ডিরেক্টরি ও কারেন্ট এনভায়রনমেন্ট প্রিফিক্স তুলনা করে venv স্ট্যাটাস নিখুঁতভাবে চেক করা হয়েছে।
simulated_packages: প্রতিটি এআই প্যাকেজের স্পেসিফিক ভার্সন পিন (Pinning) করার বাস্তব ফরম্যাট দেখানো হয়েছে।
pkg==ver: ভার্সন লক করার মাধ্যমে ক্লাউড ডেপ্লয়মেন্টে 'It works on my machine' সমস্যার সম্পূর্ণ সমাধান হয়েছে।
