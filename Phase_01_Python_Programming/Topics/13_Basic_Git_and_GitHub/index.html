০১ থিওরি ও মূল কনসেপ্ট (Theory & Core Concepts)

এআই ইঞ্জিনিয়ারের জন্য গিট কেন আবশ্যিক দক্ষতা?

মেশিন লার্নিং মূলত শত শত এক্সপেরিমেন্টের সমষ্টি। আপনি আজ একটি নতুন হাইপারপ্যারামিটার বা মডেল আর্কিটেকচার ট্রাই করলেন, কিন্তু কাল দেখলেন অ্যাকুরেসি কমে গেছে। গিট ছাড়া আপনি কখনোই আপনার আগের কাজ করা নিখুঁত কোডে এক ক্লিকে ফিরে যেতে পারবেন না:

  • ৩টি স্টেজ: Working Directory (যেখানে আপনি কোড লেখেন) → git add দিয়ে Staging Area (যেখানে কমিটের জন্য ফাইল সাজানো হয়) → git commit -m দিয়ে Local Repository (চিরস্থায়ী স্ন্যাপশট)।
  • Git Push: লোকাল রিপোজিটরি থেকে কোড দূরবর্তী ক্লাউড হোস্ট GitHub-এ আপলোড করা, যেখান থেকে টিমমেটরা কোড দেখতে পায় এবং Vercel স্বয়ংক্রিয়ভাবে লাইভ ডেপ্লয় করে।
  • .gitignore ফাইল: এআই প্রজেক্টে কখনোই বড় বড় ডেটাসেট (CSV), মডেল ওয়েটস (.pt, .h5) বা সিক্রেট কি গিটহাবে পুশ করবেন না। .gitignore ফাইলে তাদের নাম লিখে রিপোজিটরিকে হালকা ও সুরক্ষিত রাখতে হয়।
  • Branching: মূল main ব্রাঞ্চকে সবসময় ক্লিন ও স্টেবল রেখে নতুন ফিচার বানানোর জন্য git checkout -b feature/attention-layer দিয়ে আলাদা ব্রাঞ্চে কাজ করতে হয়।

কমিট মেসেজের নিয়ম: পরিষ্কার মেসেজ লিখুন (যেমন: Fix learning rate scheduler decay step), যাতে মাসখানেক পর দেখলেও বোঝা যায় কী পরিবর্তন করা হয়েছিল।

০২ বাস্তব কোড উদাহরণ (Real-World Code Example)

git_workflow_sim.py 
# গিট ওয়ার্কফ্লো ও .gitignore ফিল্টারিং সিমুলেশন
def check_git_staging(files_modified: list, gitignore_patterns: list) -> dict:
    staged = []
    ignored = []
    
    for filename in files_modified:
        # এক্সটেনশন বা নাম দিয়ে .gitignore চেক
        ext = os.path.splitext(filename)[1]
        if ext in gitignore_patterns or filename in gitignore_patterns:
            ignored.append(filename)
        else:
            staged.append(filename)
            
    return {"staged_for_commit": staged, "ignored_by_git": ignored}

# প্রজেক্ট ফাইল চেঞ্জেস
working_files = ["train.py", "model.pt", "dataset.csv", "README.md", "utils.py"]
gitignore = [".pt", ".csv", ".env"]

git_status = check_git_staging(working_files, gitignore)

print("--- Git Status Overview ---")
print("✅ Staged to Commit :", git_status["staged_for_commit"])
print("🔒 Protected (.gitignore):", git_status["ignored_by_git"])
print(f"\nSuggested Commit: git commit -m 'Add training loop and utility functions'")

💡 কোড বিশ্লেষণ ও ব্যাখ্যা (Line-by-Line Breakdown):

staged_for_commit: শুধুমাত্র মূল সোর্স কোড ও ডকুমেন্টেশন কমিটের জন্য স্টেজিং এ সিলেক্ট করা হয়েছে।
ignored_by_git: ভারী মডেল ওয়েটস (.pt) ও বড় ডেটাসেট (.csv) নিরাপদে ইগনোর করা হয়েছে।
git commit -m ...: প্রতিটি পরিবর্তনের অর্থপূর্ণ স্ন্যাপশট ইতিহাস তৈরি হয়েছে।
